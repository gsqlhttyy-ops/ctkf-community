# Contributing

1. Open an issue before a large behavioral or contract change.
2. Keep changes focused and add tests for changed behavior.
3. Run `python -m unittest discover -s tests -v`.
4. Run a clean requirement intake and `ctkf-community verify` smoke test.
5. Do not submit private CTKF source, Pro assets, credentials, customer data, or copied upstream code.
6. Document security, compatibility, license, and user-facing effects.

Unless explicitly marked otherwise, an intentional contribution is submitted
under Apache-2.0 as described by section 5 of the license.
